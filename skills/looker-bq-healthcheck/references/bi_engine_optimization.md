# BigQuery BI Engine & Memory Sizing Optimization Guide

**BigQuery BI Engine** is a fast, in-memory analysis service built directly into BigQuery that accelerates SQL queries generated by Looker to sub-500ms response times without consuming project slots or requiring caching middleware.

## 🛠️ 2. SQL Compatibility & Full Acceleration Patterns

To ensure Looker queries achieve **100% Full Acceleration (BI Engine Mode: `FULL`)** rather than falling back to standard slots:

| Feature / Syntax | Accelerated by BI Engine (`FULL`) | Triggers Fallback (`DISABLED` / `PARTIAL`) |
| :--- | :--- | :--- |
| **Join Type** | Standard Equi-Joins (`A.id = B.id`) | Non-equi joins (`A.val > B.val`), Cross joins (`type: cross`) |
| **Join Conditions** | Clean dimension references (`${orders.user_id}`) | Functions in join keys (`LOWER(TRIM(...))`, `REGEXP_CONTAINS`) |
| **Aggregations** | `SUM`, `COUNT`, `AVG`, `MIN`, `MAX` | Complex user-defined JavaScript UDFs in aggregations |
| **Window Functions**| Standard ranking and cumulative sums | Heavy nested analytical partitions with non-constant frames |
| **Table Types** | Partitioned and clustered BigQuery physical tables | Non-materialized multi-layer derived tables |

---

## 📊 3. Sizing & Capacity Allocation Formula

$$\text{Recommended BI Engine Reservation (GB)} = \sum \text{Hot Table Partitions (30 Days)} \times 1.25$$

### Sizing Guidelines:
1. **Target Tables**: Focus BI Engine reservations on high-frequency fact tables (`order_items`, `events`) and LookML `aggregate_table` rollup tables.
2. **Region Alignment**: Ensure the BI Engine reservation is created in the exact same region as your dataset (e.g. `US` multi-region or `us-central1`).
3. **Monitoring Acceleration**: Query `INFORMATION_SCHEMA.JOBS_BY_PROJECT` checking `bi_engine_statistics.bi_engine_mode` for `"FULL"`.
