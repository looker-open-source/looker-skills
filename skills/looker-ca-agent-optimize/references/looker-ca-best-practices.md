# Looker Conversational Analytics (CA) Best Practices

Internal API 4.0 schema, 4-part YAML contract, role-based permission matrix, System Activity telemetry, Looker MCP filter rules, and CLI execution standards enforced by `looker-ca-agent-create` and `looker-ca-agent-optimize`.

> **User-Facing UX Rule:** Apply all rules below internally—never expose raw YAML/XML blocks, `/x/<slug>` internals, `.lkml` diffs, or `"Plan A / Plan B"` menus to the end user unless requested (or in MCP-only fallback mode without `looker-cli`).

## 1. Four-Part System Instructions Schema (Human-Readable Root-Level YAML)

Looker displays `context.instructions` directly as plain text in **Edit Agent -> Instructions** and passes it to the CA API (`system_instruction`). Never write unstructured prose, XML wrapper tags (`<agent_instructions>`), or HTML/XML entities (`&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;`). Use natural symbols (`&`, `<`, `>`, `>=`, `<=`) inside a **4-part root-level YAML** structure (**drafting target: `3,200-4,200` chars / `~55-70` lines**; **hard cap: `<= 4,800` chars** / `< 1,200` tokens; zero root wrapper key, zero `	` tabs), validated once inside the single final atomic deployment script:
1. **`role_and_tone:`** — Persona, target audience, dataset date range (`min_date` to `max_date`), and strict Explore/Dashboard boundary prohibiting fabricated metrics.
2. **`explore_and_filtering_rules:`** —
   - Route topics to designated Explores and document BigQuery partition/join or Liquid `_is_filtered` guardrails discovered in `.lkml` or `get_explore`.
   - Apply conditional default date windows **only** to undated general trend/Top-N queries; exempt dataset-overview, lifetime, and specific entity/ID lookups to prevent `0-row` Data-Hunting loops.
   - **Complete-Day Date Syntax (`"30 days ago for 30 days"`):** Use `"30 days ago for 30 days"` (or `"90 days ago for 90 days"`, `"7 days ago for 7 days"`, `"last 1 month"`). `"last 30 complete days"` fails with **`HTTP 400 Invalid date filter syntax`**, and bare `"7 days"` includes today's partial day.
   - **String Null-Exclusion Syntax (`"-NULL"`, Never `"not null"`):** On `type: string` dimensions, Looker treats `"not null"` as literal `= 'not null'` (`0 rows`)—this **overrides** the Looker MCP `query` tool prompt note (`"Use not null instead of -NULL"`), which only applies to numeric/date fields. Always use **`"-NULL"`** (or **`"-NULL,-EMPTY"`**).
   - Inline verified categorical filter value mappings sampled from live data so the agent skips Field-Sampling loops.
3. **`semantic_and_execution_rules:`** — Disambiguate closely named measures, dimensions, currency fields, and `filter_only` parameters; enforce single-query consolidation (retrieving all dimensions, measures, and period comparisons in one Looker query).
4. **`presentation_and_analysis_rules:`** — Default grouping granularities, Top-N limits/sorts, and currency/percentage formatting.

## 2. API 4.0 Grounding, Role Permission Matrix & Least-Privilege Sharing

- **Looker API 4.0 `Agent` / `WriteAgent` (`POST /api/4.0/agents` & `PATCH /api/4.0/agents/{id}`):**
  - Mandatory on `create_agent`: `"name"`, `"description"`, and `"sources"` (`[{"model": "<model>", "explore": "<explore>"}]`). Looker API 4.0 has **no `dashboard_id` field**.
  - **Standalone Agents:** Ground on `1-5` curated Explores (advise against uncurated mega-explores with `> 15` joined views), omit `"category"` (or use `"conversation"`), and link `3-15` verified Golden Queries via `"golden_query_ids": [<int_id>, ...]`.
  - **Dashboard Agents (`"category": "dashboard"` & Native Panel Binding):** Set `"category": "dashboard"`, `"name": "<instance_origin>-<dashboard_id>"`, populate `"sources"` from tile Explores via `get_dashboard`, **omit `"golden_query_ids"`** (dashboard tiles serve as exemplars), and encode dashboard filter inheritance and tile-to-measure mappings in `context.instructions`. Because `GET /api/4.0/agents/{id}` (`get_agent "<id>"`) returns **`HTTP 404`** on `"category": "dashboard"` agents, always list, inspect, and back up Dashboard Agents via `search_agents --category "dashboard" --limit 50`, and update existing `<instance_origin>-<dashboard_id>` records in place via `update_agent "<id>" -`.
- **Role-Based Permission Pre-Flight Matrix:**
  - **Viewer (`can.create == false` / `can.update == false`, lacks `save_agents`):** In `create`, inform them in Step 1 that the *Conversational Analytics Agent Manager* role (`save_agents` permission) is required and list existing agents where `can.chat == true`. In `optimize`, run in **Read-Only Diagnostic Mode** (`Audit only` verdict) and output a shareable report for the agent owner/Admin.
  - **Agent Creator / Business Analyst (`save_agents`, lacks `develop`):** When `get_project_files` returns `403`/empty, set `has_develop_permission = false`, skip `.lkml` file reads (using `get_explore` if available to check `always_filter` / `conditionally_filter` plus `get_dimensions`/`get_measures`/`get_filters`/`get_parameters` and `query`), and at Gate #2 provide a copy-ready **Note for Your LookML Developer** (including upgraded LookML agent blocks if `is_lookml == true`) instead of offering `dev_mode`.
  - **LookML Developer (`save_agents` + `develop`):** Full `.lkml` inspection, `is_lookml: true` LookML agent updates (resolving project-relative file paths from `lookml_edit_uri` / `get_project_files`, or exporting UI agents via `looker-cli api conversationalanalytics agent_lookml "<id>"`), and optional `dev_mode` LookML metadata edits.
  - **Looker Admin (`see_system_activity`):** In `optimize`, query `model: "system__activity"` (`explore: "conversations_feedback"` and `explore: "history"` with `query_api_client_context.name: "Conversational Analytics"`). On `403`, show a 1-line tip recommending Admin execution for System Activity telemetry; on `0` rows, proceed seamlessly.
- **Least-Privilege Default & Group Sharing (`content_metadata_id`):** Standalone Agents default to creator-private access (`Manage Access, Edit`). Confirm this at Gate #2 and offer optional `View` sharing (`looker-cli api group all_groups` + `looker-cli api content create_content_metadata_access -` with `{"content_metadata_id": "<id>", "group_id": "<gid>", "permission_type": "view"}`). Dashboard Agents inherit access from their parent Dashboard's folder/content metadata.
- **Default `code_interpreter: false`:** LookML field `description:` metadata and Golden Queries are injected automatically (never dump raw field catalogs into `context.instructions`). Keep `"code_interpreter": false` by default (saving `+15s to +20s` per turn from `python_and_chart_agent`).

## 3. Golden Query Contract, Parallel Execution & Auth Fail-Fast

- **Looker MCP Parameter & Golden Query Contract (`< 20` Total Cap, `<= 50%` Eval Overlap):**
  - Looker MCP tools (`get_dimensions`, `get_measures`, `get_filters`, `get_parameters`, `get_explore`, `get_field_value_suggestions`, `query`, `query_url`) take schema keys `model` and `explore` (plus integer `limit`, `tz`, and flat object `filters` with bare `"view.field": "expr"` keys—never `"filters": null` or bracketed `"f[view.field]"`).
  - Always verify candidate Golden Queries via `query` first (`0` SQL errors, `> 0` rows) before calling `query_url` for `/x/<slug>` links.
  - `WriteGoldenQuery` (`create_golden_query -` / `update_golden_query "<gq_id>" -`): `{"questions": ["<single_question>"], "answer": "https://<host>/x/<22_char_slug>"}` (1 question per entry; omit read-only `is_active`).
- **Capped Parallel MCP Batches (`<= 8` Calls/Turn) & Concurrent Atomic CLI Execution:**
  - Keep parallel MCP batches to `<= 8` calls/turn. Do not call `get_explore` on top of `get_dimensions` + `get_measures` except when `has_develop_permission == false` to read `always_filter` / `conditionally_filter` (`< 1 KB`).
  - Inside the single atomic `python3 - <<'PY'` script, run `search_agents` (`--limit 50` and `--category "dashboard" --limit 50`) and `create_golden_query` / `update_golden_query` concurrently via `concurrent.futures.ThreadPoolExecutor`. For `[TMP-SXS-EVAL]` artifacts and test conversations, always execute **two-step soft+hard cleanup** (`update_* {"deleted": true}` then `delete_*`).
- **Auth Fail-Fast:** On `403`, adapt per Section 2. On MCP `401` or CLI `400 invalid_grant` / `404 login`, try at most **1** `get_models` re-handshake; never loop on `looker-cli --help` or `session login`/`logout`—halt and ask the user to refresh Looker API 4.0 credentials (`looker-cli profile add default --host "$LOOKER_HOST" --port 443 ...`, never `--base-url`).
