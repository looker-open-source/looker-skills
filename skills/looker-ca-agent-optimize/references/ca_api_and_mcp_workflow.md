## 2. Step 6: Apply Approved Changes (Atomic Backup Verification & Agent Update — Lines 14-21)

Execute Step 6 **only after user approval at Gate #2** (or immediately if the user's prompt explicitly requested applying the changes without waiting, and `can.update == true`):
- **LookML-Defined Agents (`"is_lookml": true`):** `PATCH /api/4.0/agents/{id}` is rejected or overwritten on LookML agents. Skip `update_agent`. If `has_develop_permission == true`, resolve the project-relative `.lkml` path from `lookml_edit_uri` + `get_project_files` and apply the approved agent instructions/golden queries in `dev_mode` (or export via `looker-cli api conversationalanalytics agent_lookml "<id>"`). **If `has_develop_permission == false`, include the complete upgraded LookML agent instruction/golden-query block inside the Gate #2 Developer Handoff Note so it is never dropped.**
1. **Verify Backup & Validate Root-Level YAML In-Memory (`0.1s`):** Confirm `/tmp/ca_agent_backup_<id>_<ts>.json` exists (writing it if not yet saved), replace any `&amp;`/`&lt;`/`&gt;` with natural `&`/`<`/`>`, assert `len(instructions) <= 4800`, verify all 4 root-level YAML keys (`role_and_tone:`, `explore_and_filtering_rules:`, `semantic_and_execution_rules:`, `presentation_and_analysis_rules:`) at column 0 and zero `\t` tabs, and run `yaml.safe_load(instructions)` when `PyYAML` is installed.
2. **Sync Approved Golden Queries Concurrently & Update Agent (With Rollback & Safe Delete Order):** Inside one atomic `python3 - <<'PY'` script, initialize `created_gq_ids = []` and record pre-edit payloads of modified Golden Queries from `/tmp/ca_agent_backup_<id>_<ts>.json`. Inside a `try:` block, use `concurrent.futures.ThreadPoolExecutor(max_workers=5)` to update modified Golden Queries in place via `update_golden_query "<gq_id>" -` (`{"questions": ["<single_question>"], "answer": "https://<host>/x/<slug>"}`) and register net-new ones via `create_golden_query -` (`< 20` total cap), appending every returned new ID to `created_gq_ids` as futures finish; then call `update_agent "<agent_id>" -` preserving `"name"`, `"description"`, and `"sources"` while updating approved `"context": {"instructions": ...}`, `"code_interpreter"`, and `"golden_query_ids"`. On any failure (`except`), delete all IDs in `created_gq_ids` via `delete_golden_query` and restore modified Golden Queries from backup before re-raising. **Only after `update_agent` succeeds**, remove obsolete Golden Queries directly via `delete_golden_query "<old_id>"`. Confirm the applied changes, agent link, and rollback backup path.

## 3. `Optimize` (`Advanced` / `Hard`) Mode: Eval Suite Ingestion, `[TMP-SXS-EVAL]` Draft Clone & Cleanup *(Step 4 — Lines 23-32)*

Execute Step 4 **only in `Optimize` (`Advanced` / `Hard`) mode**:
1. **Ingest Structured Eval Suite (`3-5` Questions Recommended) or Auto-Generate:**
   - Support `(question, ground_truth, issue_description)` from: **(a) Inline Text / Markdown Table**, **(b) Local `.csv` / `.tsv` File** via `csv.DictReader` (matching `question`, `ground_truth`/`expected_answer`, `issue_description`/`notes` case-insensitively), or **(c) Google Sheets URL / ID** via Drive/Sheets tools or CSV export.
   - If omitted, pull top failing/slow questions from Step 2 `system__activity.conversations_feedback` or auto-generate `3-4` realistic questions grounded in the Explore. Compare baseline and candidate answers against live Looker MCP `query` Ground Truth and use `issue_description` to target root-cause fixes.
2. **Run Baseline & Draft `[TMP-SXS-EVAL]` Clone Traces Without Publishing (`try/finally` Cleanup):**
   - For each question, run `create_conversation -` (`{"agent_id": "<id>", "name": "[TMP-SXS] Qn"}`) and `conversational_analytics_chat -` (`{"conversation_id": "<conv_id>", "user_message": "<question>"}`), recording directional latency (P50/P90), accuracy count (e.g., `4 of 5`), `systemMessage.text` (`textType == "THOUGHT"`), `systemMessage.data.generatedLookerQuery`, and whether `code_interpreter` triggered unnecessarily.
   - Test the draft config **without modifying the live agent** inside a **`try / finally`** block tracking `tmp_conv_ids = []`, `tmp_agent_id = None`, and `tmp_gq_ids = []`: register fresh temporary Golden Queries via `create_golden_query -` (never reuse live `golden_query_ids`, appending each created ID to `tmp_gq_ids`), create an isolated clone via `create_agent -` (`"name": "[TMP-SXS-EVAL] <Original Name>"`, `"description"`, `"sources"`, candidate `"context"`, `"code_interpreter"`, and `"golden_query_ids": tmp_gq_ids`), and run **Round 1** (and **Round 2 [final]** only if Round 1 did not improve with 0 regressions).
   - **Always purge in `finally:`** (even if Golden Query creation, `create_agent`, or any chat call fails or times out): remove temporary conversations and the `[TMP-SXS-EVAL]` clone agent via **two-step soft+hard cleanup** (`update_*` with `{"deleted": true}` followed by `delete_*`), and delete every ID in `tmp_gq_ids` directly via **`delete_golden_query "<gq_id>"`** (Golden Queries cannot be soft-deleted).
